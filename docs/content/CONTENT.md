# ONE PERSON UNICORN — Canonical Content Contract

Status: BINDING CONTENT + WRITING AUTHORITY FOR V2

Product mechanics are owned by `../../ONE_PERSON_UNICORN_CANONICAL_CONTEXT_V2.md`. Economic values/effect magnitudes are owned by `../balance/BALANCE_SPEC_V2.md` and `../../balance/v2/registry.json`. Presentation is owned by `../design/DESIGN.md`.

Content makes the deterministic systems culturally sharp, funny, understandable and replayable. It must never become a hidden balance layer.

## 1. Content thesis

The cultural center of ONE PERSON UNICORN is:

> **ONE-PERSON AI COMPANY**

not “vibe coding” alone.

The emotional arc is:

```text
AI IS MAGIC
→ AI SAVES ENORMOUS TIME
→ ADD MORE AGENTS
→ MORE OUTPUT
→ MORE HANDOFFS
→ MORE COMPLEXITY
→ MORE CONTEXT ROT
→ AGENTS DO WEIRD THINGS
→ FOUNDER BUILDS SYSTEMS TO CONTROL THEM
→ THE AUTONOMOUS COMPANY BECOMES A FULL-TIME JOB
```

Content should make that arc legible through specific founder situations, not generic AI jokes.

## 2. Content domains

Authored deterministic content includes:

- Product recipes and component semantics;
- customer/cohort archetypes;
- Marketing opportunity archetypes;
- Retention threats;
- Operations obligations and optimization scratchers;
- Finance offer/obligation archetypes;
- Founder Histories;
- quarterly Strategies;
- Relics / “What Changed?” cards;
- incidents and cross-function events;
- tutorials/onboarding strings;
- achievements/challenges/endings;
- versioned culture packs;
- build labels and run summaries;
- brand-safe flavor/name pools.

Target breadth from product canon includes approximately 224 Relics and 42 Strategies, but catalogue completion must follow engine validation rather than precede it.

## 3. Content versus mechanics

Content may:

- select a deterministic recipe;
- reference a stable semantic action/effect ID;
- declare eligibility/trigger conditions through approved schemas;
- supply player-facing names, descriptions and flavor;
- supply localization context;
- select authored visual/audio themes;
- define deterministic content variants.

Content must not:

- calculate ARR, valuation, debt, ownership, probability or rewards independently;
- hide balance constants in copy or JSON;
- bypass simulation with ad-hoc component behavior;
- invent a numeric effect because a card “needs something”; 
- use a live model to determine economic resolution.

If a content idea needs a new mechanic/effect, define the product/balance dependency explicitly before authoring it as shippable content.

## 4. Player-facing writing hierarchy

Every player-facing string resolves in this order:

```text
CLARITY
→ CONTEXT
→ PERSONALITY
→ CULTURAL REWARD
```

A joke that obscures the mechanic fails.

Preferred two-layer structure:

**Memorable name / headline**  
Plain-language mechanical consequence.

Examples of the pattern, not canonical strings:

- **Actually Read the Diff**  
  Product work takes longer; verified ships become safer.

- **One More Agent**  
  Add a Worker Agent. Complexity increases.

- **Everything Is Fine™**  
  Operations risk rises faster; crisis upside also improves.

The name earns attention. The effect line protects comprehension.

## 5. Voice

Player-facing language should be:

- concise;
- specific to startups/operators/AI companies;
- mechanically literate;
- funny when the situation deserves it;
- culturally aware without trying to sound chronically online;
- confident rather than corporate;
- readable under pressure.

Avoid:

- MBA-language soup;
- generic “AI-powered” copy;
- fake founder inspiration;
- endless meme slang;
- jokes that could belong to any roguelite;
- exposition where six words plus visible state would teach more effectively.

Default copy targets:

- navigation: 1–3 words;
- action: verb-led;
- alert preview: one sentence or less;
- Relic/Strategy effect: readable in roughly two seconds;
- tooltip: mechanic first, flavor second;
- tutorial: one action at a time;
- failure explanation: direct causal language.

## 6. Cultural literacy

Useful content territory includes:

- one-person unicorn discourse;
- AI replacing teams;
- agent sprawl;
- context windows and context rot;
- parallel agents;
- recursive automation;
- model/provider churn;
- tool subscriptions;
- cloud bills;
- permissions and approval bottlenecks;
- AI product sameness;
- eval failures;
- prompt/context hygiene;
- support automation;
- growth/product/operator folklore;
- financing hype and financing reality;
- bootstrap/debt/VC tension;
- demo-to-production gaps;
- open-source/community dynamics;
- enterprise procurement/security realities.

Deep “ball knowledge” is encouraged when it produces recognition and specificity. It is bonus meaning, never required meaning.

The more permanent the UI surface, the more durable the language should be. Fast-moving references belong mainly in culture packs, incidents, Relics, achievements and other replaceable/versioned content.

## 7. Culture-pack workflow

Never paste a current post, meme, article sentence or creator joke directly into the game.

Use:

```text
RESEARCH CURRENT CULTURE
→ EXTRACT RECURRING IDEA/PATTERN
→ MAP TO AN EXISTING GAME SYSTEM OR PROPOSE A CLEAR DEPENDENCY
→ WRITE AN ORIGINAL FICTIONAL ARCHETYPE
→ WRITE ORIGINAL PLAYER-FACING COPY
→ REVIEW FOR MECHANICAL CLARITY + IP SAFETY + SHELF LIFE
→ SHIP AS VERSIONED CONTENT
```

Record source notes for research provenance where useful, but never expose copied protected expression in shipped content.

## 8. Copyright, trademark and likeness safety

Content may reference broad cultural ideas, industry patterns and factual concepts. It must remain original.

Do not ship:

- copied meme text/art;
- copied posts/tweets;
- lyrics;
- recognizable protected characters;
- another game's item/card names where distinctive;
- third-party logos as flavor decoration;
- confusingly similar brand marks;
- celebrity/influencer likenesses without an approved reason/right;
- quotes presented as original game copy.

A real company/product may be discussed factually in research. Prefer fictionalized or genericized player-facing content unless the real name is necessary and legally/product-wise appropriate.

“Founder folklore” should be transformed into original situations, not quote collections.

## 9. Relic contract

Internal system: `Relic`.

Quarter-close presentation should normally frame the choice semantically, such as **What Changed?**, rather than forcing RPG terminology into the fiction.

Every Relic needs:

```text
stable id
name
plain-language effect summary
effect reference(s)
eligibility reason/rule
tradeoff or catch when present
rarity/presentation metadata when relevant
flavor line only if it adds value
localization context
tags/build-family signals
```

Relics should primarily create interesting changes to:

- rules;
- routing;
- timing;
- risk;
- capacity;
- probability through approved effect contracts;
- cross-function causality.

Avoid a catalogue dominated by anonymous `+10% / +15% / +20%` modifiers.

Eligibility must be understandable. When a build unlocks a new Relic family, the UI should be able to explain why it became available.

## 10. Quarterly Strategy contract

Strategies are intentional founder-level operating decisions, distinct from Relics.

Every Strategy needs:

```text
stable id
name
plain-language thesis
duration/expiry contract
benefit(s)
cost/tradeoff(s)
effect reference(s)
eligibility if contextual
localization context
build-family tags
```

A Strategy must change how the company is operated, not merely offer a disguised generic stat bonus.

Good shape:

**Enterprise Upmarket**  
Larger customer opportunities. Product recipes and Operations pressure become harder.

The exact magnitudes come from locked balance, not prose.

## 11. Founder History contract

Founder History is explicitly selected by the player.

Never infer the player's real history, identity or experience from accounts, browsing, device data or connected services.

A History may:

- unlock a starting Relic;
- weight or unlock complementary paths;
- alter early Finance access through approved effects;
- encourage an off-meta build.

It may not directly multiply valuation.

Fresh Founder remains the standardized comparison baseline unless product canon changes.

## 12. Product recipe contract

Product recipes are deterministic content.

A recipe defines semantic ingredients/components and valid assembly stages, not economic output math.

Each recipe should provide:

```text
stable recipe id
request/name
component ids
assembly/dependency structure
verification/testing semantics
ship states
failure/rework content cues
customer/segment relevance tags
localization context
```

Recipes must remain understandable through object semantics. Avoid random ingredient combinations that only exist to create difficulty.

## 13. Customer/cohort archetypes

Customer content may define semantic traits such as:

- segment;
- use case;
- needs;
- qualitative willingness-to-pay behavior;
- reliability sensitivity;
- expansion interests;
- procurement/implementation character;
- flavor/name pools.

Numeric bands, probabilities, ARR magnitudes and churn behavior must reference approved simulation/balance contracts rather than live in content prose.

Archetypes should create recognizable tradeoffs, not stereotypes about protected classes or demographic groups.

## 14. Marketing opportunities

Marketing content supplies the situation the player judges.

Useful semantic signals include:

- audience fit;
- purchase intent;
- trend velocity;
- saturation;
- acquisition cost context;
- downstream workload context;
- quality/risk clues.

The opportunity text/art should make a judgment possible while preserving the intended information uncertainty from skill level.

Do not make “funny trend name” the only skill test.

## 15. Retention threats

Threat content should communicate:

- what is going wrong;
- why this cohort/customer is at risk;
- urgency;
- semantic root cause;
- what kind of intervention is appropriate.

Examples may cover billing failure, broken workflows, outages, onboarding failure, support escalation and missing capabilities.

Retention content never claims to create positive ARR directly.

## 16. Operations content

Two distinct content families:

### Obligations

Problems already occurring: cloud/API cost spikes, retry storms, bad deployments, security warnings, duplicate workflows, context overflow, model regression, recursive automation, etc.

The goal is damage control. Scratch/reveal exposes evidence.

### Optimization Scratchers

Explicit optional high-variance bets: one-line fix, black-box optimizer, broad permissions, context compaction, global model switch, etc.

Every optimization must communicate **upside and downside before commitment**. Catastrophic tails cannot be disguised as free rewards.

## 17. Finance content

Finance copy must remain mathematically and semantically precise.

Offers/obligations may include:

- check size;
- valuation/SAFE cap;
- dilution;
- APR;
- principal;
- interest;
- covenants/control terms;
- repayment/refinance choices;
- runway implications.

Content labels the terms; simulation/balance computes them.

Never imply that funding itself creates ARR or valuation.

Avoid fabricated legal precision when the game mechanic only models an abstraction. If a finance concept is simplified, communicate the simplification through the system rather than pretending it is a complete real-world contract.

## 18. Tutorials and onboarding content

Tutorial content follows:

```text
POINT
→ DO
→ PROVE
```

Every tutorial specifies:

- trigger/first relevance;
- exact action;
- visual focus target;
- expected visible consequence;
- short success confirmation;
- replay/help reference.

Do not front-load future mechanics. Explain an agent failure when the player first experiences a meaningful agent failure; explain debt when debt becomes relevant; explain Rot after autonomy gives the player a reason to care.

## 19. Failure and run-summary writing

Failure attribution is a replay mechanic, not flavor.

The result must explain:

- what killed the company;
- when the failure began;
- which function became the bottleneck;
- which build emerged;
- which major decisions contributed.

Prefer causal sentences over moral judgment.

The system should distinguish failure types such as Growth Mandate miss, bankruptcy, debt spiral, automation collapse, churn spiral and context corruption when supported by simulation state.

## 20. Secret/milestone content

Major milestones such as $10M, $100M, $1B and beyond may earn stronger authored language and visual choreography.

The hidden $1T AI-takeover ending should remain unadvertised in normal achievement surfaces unless product canon explicitly changes.

Secret content should be discoverable through play, not spoiled by generic onboarding copy.

## 21. Localization contract

Every shippable string should have:

- stable string ID;
- mechanic/context note;
- tone/speaker where relevant;
- variables separated from grammar;
- reference-intent/transcreation note when culturally specific.

Avoid sentence-fragment concatenation that assumes English grammar.

Do not bake copy into generated images unless an explicitly non-localized campaign asset requires it.

When a joke cannot translate literally, preserve its function and mechanical clarity through transcreation.

## 22. Runtime GenAI boundary

Optional runtime GenAI may generate:

- fictional company/person names;
- non-authoritative surface wording;
- cosmetic flavor variants;
- original jokes constrained to an existing deterministic archetype.

It may not generate or decide:

- probabilities;
- ARR effects;
- valuation;
- skill effects;
- Strategy/Relic mechanics;
- agent reliability;
- debt/VC terms;
- reward values;
- eligibility outcomes;
- economic state transitions.

GenAI failure/offline mode must leave the deterministic authored game fully playable.

Generated text must be validated against length, safety, allowed variables and the already-resolved deterministic meaning before display.

## 23. Freshness lifecycle

Separate durable content from fast-moving culture.

Suggested content metadata:

```text
contentVersion
createdAt
reviewAfter
freshness: durable | seasonal | culture-pulse
locale
sourceNotes
```

Culture-pulse content should be reviewed/replaced without requiring balance changes.

Do not let a stale meme become a core mechanic label.

## 24. Content QA gate

Reject content if:

- the mechanic is ambiguous;
- a number appears without a locked/approved source;
- content contains hidden outcome logic;
- the joke is doing all the explanatory work;
- it reads like generic AI banter;
- it copies recognizable third-party expression;
- a cultural reference is required to understand the action;
- it creates a protected-class stereotype;
- an Operations gamble hides catastrophic downside;
- Finance wording contradicts the modeled economics;
- localization context is missing for a shippable string;
- a fast-moving reference has been placed in permanent navigation;
- runtime GenAI can change deterministic meaning.

Use `$opu-content-guardian` for authored content changes.
